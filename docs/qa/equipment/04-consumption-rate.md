# Норма расхода — сценарии для тестировщика

> Меню: **Оборудование → Норма расхода**.  
> Формат ТК: **Предусловия → Шаги → Ожидаемый результат**.

Общие предусловия раздела: план **BUSINESS / CUSTOM**, `read` или `manage` на `Incident`.

Норму ставит главный техник: коэффициенты объёма химии от времени работы программ.

---

## О странице

### Таблица норм (`/equipment/consumption/rate`)

| | |
|--|--|
| **Зачем** | Задать для объекта `literRate` и концентрацию по типам программ. |
| **Что менеджерит** | `ProgramTechRate`. API: `getConsumptionRate`, `patchProgramCoefficient`. |
| **Кто пользуется** | Главный техник: смотрит все с `read`; сохраняет при `update` или `manage` Incident. |
| **Связи** | Расход химии (coef); отчёт по расходу (quantityByReport из spent). |
| **Правила** | Query: `city`, `posId`. Без объекта таблица пустая. GET создаёт пустые записи rate, если их ещё не было. В БД значения `*100`. |

Подписи: **Норма расхода**, **Город**, **Автомойка/Филиал**, **Расход литр/минута**, **Концентрация 1/х**, **Отменить**, **Сохранить**. Placeholder фильтров: **Выберите значение**.

---

## ТК-N1. Главный техник задаёт коэффициенты

**Предусловия:** `update` или `manage` на `Incident`; выбран объект с программами.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть **Норма расхода**, выбрать город и объект | Таблица программ, поля расход и концентрация |
| 2 | Ввести неотрицательные коэффициенты → **Сохранить** | **Запись успешно обновлена** (или аналог success). Значения остаются после обновления |
| 3 | Ввести отрицательные | Поле с ошибкой, запрос не уходит (`literRate < 0` / `concentration < 0`) |

---

## ТК-N2. Без права — только смотреть

**Предусловия:** только `read` Incident, без `update`/`manage`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть экран, выбрать объект | Таблица видна |
| 2 | Искать кнопку **Сохранить** | Кнопки нет (`Can` на Incident update/manage). **Отменить** может остаться |
