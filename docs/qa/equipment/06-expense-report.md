# Отчет по расходу — сценарии для тестировщика

> Меню: **Оборудование → Отчет по расходу**.  
> Формат ТК: **Предусловия → Шаги → Ожидаемый результат**.

Общие предусловия раздела: план **BUSINESS / CUSTOM**, `read` или `manage` на `Incident`.

После отправки списание со склада ещё можно — **правило продукта**, не аналогия с инкассацией. Статья финучёта не создаётся. Складские ТК не писать: только факт документа. См. [Склад → Документы](../warehouse/02-documents.md).

---

## О странице

### Список (`/equipment/expense-report`)

| | |
|--|--|
| **Зачем** | Создать отчёт за период по объекту и открыть карточку. |
| **Что менеджерит** | `TechExpenseReport`. API: `getTechExpenseReports`, `createTechExpenseReport`. |
| **Кто пользуется** | Техслужба с `read` Incident. |
| **Связи** | Расходники объекта + chemistry spent + нормы; после SENT — склад `COMMISSIONING`. |
| **Правила** | Query: `page`, `size`, `posId`, `dateStart`, `dateEnd`. Список грузится при выбранном `posId`. Кнопка **Добавить**. Drawer title **Создание объекта** (`pos.creating`): объект, **Начало периода**, **Конец периода**, **Сохранить**. |

Колонки: **ID**, период (ссылка на edit), **Статус**, **Дата создания**, **Дата обновления**. Статусы: **Создано**, **Сохранено**, **Отправлено**.

### Карточка (`/equipment/expense-report/edit?id=`)

| | |
|--|--|
| **Зачем** | Заполнить количества, пересчитать, отправить, провести/отменить склад, вернуть. |
| **Что менеджерит** | recalculate / send / send-warehouse / cancel-warehouse / return / delete / get by id. |
| **Правила** | Правка при `CREATED` или `SAVED`. SENT: **Провести на складе** и **Вернуть**, если ещё не проведено. Если **Проведено на складе** = **Да** — **Отменить проведение по складу**. Delete — не SENT. Кнопки Can: Incident update/delete. |

Подписи строк: **Количество на начало**, **Расход по отчетам**, **Количество на складе (по документам)**, **Количество на складе (расчет)**, **Списать со склада**, **Количество на конец**, **Расход по складу**, **Приход по складу**, **Дата проведения документа по складу**. Кнопки: **Пересчитать**, **Отправить**, **Провести на складе**, **Вернуть**, **Отменить проведение по складу**.

## ТК-E1. Создать и заполнить отчёт

**Предусловия:** на объекте есть расходники; по возможности — FINISHED-задачи химии и нормы за период.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Отчет по расходу**, выбрать объект | Таблица отчётов |
| 2 | **Добавить**: объект, начало/конец периода → **Сохранить** | Отчёт **Создано**. Появляется в списке |
| 3 | Клик по периоду | `/equipment/expense-report/edit?id=`, строки расходников, **Расход по отчетам** для химии из spent, для запчастей 0 |
| 4 | При необходимости поправить **Списать со склада** / **Количество на конец** → **Пересчитать** | Статус **Сохранено**, суммы пересчитаны |

---

## ТК-E2. Отправить

**Предусловия:** отчёт `CREATED` или `SAVED`; `update` Incident.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Отправить** | Статус **Отправлено**. **Успешно отправлено** |
| 2 | Проверить статьи финучёта | Новой статьи **нет** |
| 3 | Смотреть кнопки | Есть **Провести на складе** и **Вернуть**. Поля периода не редактируются как у SAVED |

---

## ТК-E3. Списание на склад

**Предусловия:** SENT, `isWriteOffFromWarehouse=false`; у объекта есть склад; `quantityWriteOff > 0` хотя бы у одной строки.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Задать **Дата проведения документа по складу** при необходимости | Поле сохраняется в DTO send/recalculate |
| 2 | **Провести на складе** | **Проведено на складе** = **Да**. На складе объекта документ типа **Передача в эксплуатацию** (`COMMISSIONING`) с количествами списания. Статья учёта не создаётся |
| 3 | Открыть [Документы склада](../warehouse/02-documents.md) | Документ виден в списке склада. Детальные ТК склада не выполнять в этом разделе |

---

## ТК-E4. Повторное списание — факт кода

**Предусловия:** отчёт уже проведён на складе.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Смотреть карточку | Кнопки **Провести на складе** и **Вернуть** нет. Есть **Отменить проведение по складу** |
| 2 | Не вызывать повторно UI-кнопку склада | Повтор с UI недоступен |
| 3 | Факт API | Проверка склада: ошибка если `status != SENT` **и** уже проведено. Повторный POST на SENT+уже проведённом этой проверкой **не** режется. После **Отменить проведение по складу** снова доступно **Провести на складе** |
