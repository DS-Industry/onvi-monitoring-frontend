# Технические задачи — сценарии для тестировщика

> Меню: **Оборудование → Технические задачи → Список задач**.  
> Формат ТК: **Предусловия → Шаги → Ожидаемый результат**.

Общие предусловия раздела: план **BUSINESS / CUSTOM**, организация, права `TechTask`.

Правила раздела: статусы и «на проверку» — в [00-how-it-works.md](./00-how-it-works.md) (конфликт: complete сразу FINISHED).

---

## О странице

### Список задач (`/equipment/technical/tasks/list`)

| | |
|--|--|
| **Зачем** | Видеть техзадачи объектов, фильтровать, создавать, открывать карточку, массово удалять. |
| **Что менеджерит** | Список `TechTask`. API: `getTechTaskExecution` (`GET user/tech-task/me`). |
| **Кто пользуется** | Главный техник и техник АМС с `read` или `manage` на `TechTask`. |
| **Связи** | Создание в модалке; химия — задачи с тегом `TECH_RATE`; отчёт по расходу использует те же FINISHED-задачи. |
| **Правила** | Query: `posId`, `status`, `page`, `size`, `name`, `tags` (csv имён), `startDate`, `endDate`, `assigned` → `executorId`. Фильтр статусов: Действующий, Выполнено, Просрочено, Возвращена — **Приостановлена в фильтре нет**. Карточка открывается модалкой, не `/list/item`. |

Колонки: **№**, **Автомойка/ Филиал**, **Наименование работ**, **Статус**, **Тип работы**, **Теги**, **Крайний срок**, **Автор**, **Исполнитель**. Звезда у `templateToNextCreate`. Кнопка **Создать задачу** — `create` или `manage`.

### Создание (модалка)

| | |
|--|--|
| **Зачем** | Поставить разовую или регулярную задачу с шаблонами и тегами. |
| **Что менеджерит** | `POST user/tech-task`. |
| **Кто пользуется** | Главный техник (`create` / `manage`). |
| **Связи** | Шаблоны `GET user/tech-task/item`; теги `GET user/tech-task/tag`. |
| **Правила** | Обязательны название, комментарий автора, объект(ы), тип работы, хотя бы один тег. Регулярная: периодичность (Ежедневно / Еженедельно / Ежемесячно / Ежегодно / Кастомный период). Статус после создания — `ACTIVE`. |

Подписи: **Создать задачу**, **Введите название задачи...**, **Комментарий от автора**, **Шаблоны**, **Доступные шаблоны**, **Автомойка/Филиал**, **Тип работы**, **Одноразовая**, **Многоразовая**, **Периодичность**, **Теги**, **Создать**, **Отменить**.

### Карточка (модалка update)

| | |
|--|--|
| **Зачем** | Заполнить пункты, завершить, править, вернуть, комментировать. |
| **Что менеджерит** | `GET/PATCH user/tech-task`, `POST user/tech-task/:id`, комментарии. |
| **Кто пользуется** | Техник заполняет (`read`); главный правит и возвращает (`update`). |
| **Правила** | Вкладки **Ход выполнения**, **Комментарии к задаче**. Не edit: **Завершить**. Если статус Выполнено и есть `update` — **Вернуть в работу**. Edit: **Сохранить**, статус в т.ч. **Приостановлена**. |

## ТК-T1. Открыть список задач

**Предусловия:** `read` или `manage` на `TechTask`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | В меню открыть **Оборудование** | Раскрывается подменю **Ежедневные параметры тех.службы** |
| 2 | Нажать **Технические задачи** → **Список задач** | `/equipment/technical/tasks/list`, заголовок раздела задач |
| 3 | Дождаться загрузки | Таблица (или пустая). Есть поиск **Поиск задач...**, фильтры, при праве create — **Создать задачу** |

---

## ТК-T2. Создать разовую задачу

**Предусловия:** `create` или `manage`; есть объект и хотя бы один тег и шаблон.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Нажать **Создать задачу** | Модалка создания |
| 2 | Не заполнять название → **Создать** | Ошибка **Название задачи обязательно** |
| 3 | Заполнить название, **Комментарий от автора**, объект, тип **Одноразовая**, дату окончания, тег, перенести шаблон в выбранные → **Создать** | **Задача успешно создана**. В списке статус **Действующий**, тип **Одноразовая** |

---

## ТК-T3. Создать регулярную задачу

**Предусловия:** как Т2.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Создать задачу**, тип **Многоразовая** | Появляется **Периодичность** |
| 2 | Не выбрать периодичность → **Создать** | Валидация **Выберите тип периода для регулярных задач** |
| 3 | Периодичность **Ежедневно** (или иная), шаблоны, теги, объект → **Создать** | Задача `REGULAR`, `ACTIVE`. У родителя `templateToNextCreate` (звезда в списке). Следующую копию создаёт cron в `00:00` бизнес-TZ |

---

## ТК-T4. Набор заготовленных проверок (шаблоны)

**Предусловия:** в `GET user/tech-task/item` есть шаблоны.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть создание | Блоки **Доступные шаблоны** и выбранные |
| 2 | Отметить шаблоны, стрелка в выбранные | Счётчик выбранных растёт |
| 3 | Сохранить задачу, открыть карточку | Вкладка **Ход выполнения**: **Заполнение шаблонов** с теми же полями |

---

## ТК-T5. Тег «Расход химии»

**Предусловия:** в справочнике тегов есть тег, который должен включать задачу в химию.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Создать/открыть задачу, в **Теги** выбрать тег с именем вроде «Расход химии» | Тег виден в карточке и колонке **Теги** |
| 2 | Завершить ≥ 2 таких задачи за период и открыть **Расход химии** | См. конфликт: |

1. **Продукт:** тег «Расход химии» включает задачу в расчёт химии.
2. **Код:** в расчёт попадают задачи с `code = TECH_RATE`, не по имени. Если у тега нет этого code — в chemistry-report задачи нет.

---

## ТК-T6. Техник отправляет на проверку

**Предусловия:** есть `ACTIVE` задача с шаблонами; пользователь с `read` TechTask (техник объекта), без обязательного `update`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть задачу в списке | Модалка, не `/list/item` |
| 2 | Заполнить поля шаблонов на **Ход выполнения** | Значения в форме |
| 3 | Нажать **Завершить** | См. конфликт: |

1. **Продукт:** ответ уходит на проверку главному технику.
2. **Код:** статус сразу **Выполнено** (`FINISHED`). Кнопки **Вернуть в работу** у техника без `update` нет.

---

## ТК-T7. Главный техник возвращает

**Предусловия:** задача `FINISHED`; пользователь с `update` или `manage` TechTask.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть завершённую задачу | Поля можно смотреть; **Завершить** нет |
| 2 | Нажать **Вернуть в работу** | Статус **Возвращена** (`RETURNED`). Задачу снова можно заполнять и завершать |

---

## ТК-T8. PAUSE регулярной

**Предусловия:** есть `REGULAR` с `templateToNextCreate=true`; `update` TechTask.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть задачу → режим редактирования | Поле **Статус** |
| 2 | Выбрать **Приостановлена** → **Сохранить** | Статус **Приостановлена**. `templateToNextCreate=false`, `nextCreateDate` пустой |
| 3 | Дождаться cron | Новая регулярная копия **не** создаётся |

---

## ТК-T9. FINISHED: смотреть и вернуть в работу

**Предусловия:** задача **Выполнено**.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть задачу | Карточка открывается, шаблоны видны, редактирование значений ограничено статусом |
| 2 | При `update` нажать **Вернуть в работу** | Как Т7: **Возвращена** |

---

## ТК-T10. OVERDUE

**Предусловия:** задача `ACTIVE` или `RETURNED`, `endSpecifiedDate` не позже конца вчерашнего дня в бизнес-TZ cron.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Дождаться cron `00:00` (или убедиться, что дата срока уже в прошлом относительно вчера) | Статус **Просрочено** |
| 2 | Отфильтровать список по **Просрочено** | Задача в выборке |
