# Поломки оборудования — сценарии для тестировщика

> Меню: **Оборудование → Поломки оборудования**.  
> Формат ТК: **Предусловия → Шаги → Ожидаемый результат**.

Общие предусловия раздела: план **BUSINESS / CUSTOM**, организация, права `Incident`.

Поломка ≠ техзадача. Спец. статус работника — [00-how-it-works.md](./00-how-it-works.md).

---

## О странице

### Список и формы (`/equipment/failure`)

| | |
|--|--|
| **Зачем** | Фиксировать и закрывать поломки на объекте: полная форма техника и упрощённое заявление. |
| **Что менеджерит** | `Incident`. API: `getIncident`, `createIncident`, `updateIncident`, `createSimpleIncident`. |
| **Кто пользуется** | Техник объекта (`update` / `create` / `read`); работник только этой страницы (спец. статус) — упрощённо. |
| **Связи** | Справочники узлов `getEquipmentKnots` / `getIncidentEquipmentKnots`, устройства, программы, работники. Не связана с техзадачами. |
| **Правила** | Query: `posId`, `dateStart`, `dateEnd`, `city`. Кнопка **Заявить о поломке** — `create` или `manage`. **Зафиксировать поломку** — `update` или `manage`. Колонка правки — при `update`. |

Колонки: **Название объекта**, **Сотрудник**, **Дата поломки**, **Дата начала работы**, **Дата окончания работы**, **Устройство**, **Вид оборудования**, **Узел**, **Проблема**, **Причина**, **Предпринятые меры**, **Время исправления**, **Простой**, **Комментарий**, **Программа**, **Статус** (**Новый** / **Решен**).

Полная форма (в т.ч. **Простой**) — drawer **Зафиксировать поломку**. Simple: объект, сотрудник, дата появления, комментарий.

Пустые тексты: **В этом разделе отображаются поломки оборудования**, **На данный момент у вас нет зафиксированных поломок**.

## ТК-B1. Создать поломку техником объекта

**Предусловия:** `update` или `manage` на `Incident`; есть объект, устройства, узлы.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть **Поломки оборудования** | `/equipment/failure`, заголовок «Поломки оборудования» |
| 2 | Нажать **Зафиксировать поломку** | Drawer полной формы: объект, сотрудник, даты, устройство, узел, проблема, причина, меры, **Простой**, комментарий, программа |
| 3 | Заполнить обязательные поля → сохранить | Запись в таблице. Статус в коде полного POST — **Решен** (`RESOLVED`, default prisma) |

---

## ТК-B2. Создать упрощённо работником только этой страницы (спец. статус)

**Предусловия:** пользователь — работник объекта с доступом только к этой странице (спец. статус). В коде отдельной роли нет: ориентир — `create` Incident без `update` / без `read` на остальные экраны.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Войти этим пользователем | В меню **Оборудование** виден пункт **Поломки оборудования**. Экраны химии/норм/отчёта при отсутствии `read` Incident **не** видны |
| 2 | Нажать **Заявить о поломке** | Drawer: объект, сотрудник, дата, комментарий. Полной формы нет, если нет `update` |
| 3 | Сохранить | Инцидент со статусом **Новый**. См. конфликт: |

1. **Продукт:** спец. статус, доступ только к этой странице, техник проверяет.
2. **Код:** `POST user/incident/simple`, статус `NEW`. Отдельного user status нет.

---

## ТК-B3. Техник проверяет упрощённую поломку

**Предусловия:** есть инцидент **Новый** (simple); техник с `update` Incident.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть список, найти запись **Новый** | Строка в таблице, статус оранжевый **Новый** |
| 2 | Нажать редактирование | Форма с полями полной карточки |
| 3 | Дозаполнить узел/причину/меры/**Простой** при необходимости | Данные сохраняются в форме до отправки |

---

## ТК-B4. Закрыть / обновить

**Предусловия:** есть инцидент; `update` или `manage`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть запись → сохранить PATCH | Статус всегда **Решен** (`RESOLVED`), независимо от того, меняли ли поля статуса вручную |
| 2 | Обновить список | Тег статуса зелёный **Решен** |
