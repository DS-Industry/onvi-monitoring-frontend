# Расчет ЗП — сценарии для тестировщика

> Меню: **HR → Расчет ЗП**.  
> Формат ТК: **Предусловия → Шаги → Ожидаемый результат**.

Общие предусловия: план **SPACE** / **BUSINESS** / **CUSTOM**, права `Hr`.

**Табель** — только предусловие: отправленные рабочие смены за месяц.

---

## О странице

### Список ЗП (`/hr/salary`)

| | |
|--|--|
| **Зачем** | Видеть сохранённые зарплаты, премию/штраф/безнал, удалить ошибочный отчёт. |
| **Что менеджерит** | **HrPayment** типа `PAYMENT`. |
| **Кто пользуется** | Управляющий / HR с `read`. Создать — `create` / `manage`. Правка и удаление — `delete` / `manage`. |
| **Связи** | Аванс за тот же месяц (вычитается), смены, ставки АМС. |
| **Правила** | **Бизнес:** одна ЗП на сотрудника в месяц. **Код:** calculate прячет, если уже есть `PAYMENT`; повторный create через API возможен; unique нет. `HrPayment.sum` после сохранения не пересчитывается. |

### Создание (`/hr/salary/creation`)

| | |
|--|--|
| **Зачем** | Посчитать ЗП по сменам, вычесть аванс (если был), проставить премию/штраф. |
| **Что менеджерит** | Calculate PAYMENT + create. |
| **Кто пользуется** | Управляющий с `create` / `manage`. |
| **Связи** | Аванс не обязателен. |
| **Правила** | К выплате на UI: `начислено − аванс + премия − штраф`; итог ещё минус безнал. Комментарий необязателен. Нет смен → пустой список. |

Формулы и расхождения: [00-how-it-works.md](./00-how-it-works.md).

## ТК-Z1. Открыть список ЗП

**Предусловия:** право `read`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **HR → Расчет ЗП** | `/hr/salary`, заголовок «Расчет ЗП» |
| 2 | Дождаться загрузки | Таблица или пусто. Колонки ориентир: ФИО, месяц, дата выдачи, посменное начисление, смены, выплачено аванс, основная часть ЗП, премия, штраф, безналичная выплата, к выплате |

---

## ТК-Z2. ЗП при уже созданном авансе

**Предусловия:** по сотруднику за месяц есть аванс и отправленные смены. Право `create` / `manage`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Рассчитать ЗП** | `/hr/salary/creation` |
| 2 | Организация, **Расчётный месяц** → **Сформировать** | Строка: начислено по сменам, **Выплачено аванс** > 0, к выплате меньше полной суммы на `аванс` |
| 3 | Сохранить | Запись в списке ЗП; аванс вычтен |

---

## ТК-Z3. ЗП без аванса

**Предусловия:** смены есть, аванса за месяц нет.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Сформировать** | **Выплачено аванс** = 0; к выплате от начисленного по сменам |
| 2 | Сохранить | ЗП создаётся без аванса — так и задумано |

---

## ТК-Z4. Премия и штраф

**Предусловия:** открыто создание, есть строка calculate.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Ввести **Премия** и **Штраф** ≥ 0 | Поля приняты |
| 2 | Смотреть **К выплате** | `начислено − аванс + премия − штраф` |
| 3 | Заполнить **Безналичная выплата** | **К выплате итог** меньше на эту сумму |
| 4 | Сохранить | Значения в списке ЗП |

На UI нельзя сохранить с пустой/отрицательной премией или штрафом (нужны числа ≥ 0).

---

## ТК-Z5. Комментарий необязателен

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Оставить комментарий пустым, заполнить дату и премию/штраф ≥ 0 → сохранить | ЗП создаётся |
| 2 | Указать комментарий → сохранить | Комментарий хранится, на сумму не влияет |

---

## ТК-Z6. Вторая ЗП за тот же месяц

**Предусловия:** ЗП по ТК-Z2 или Z3 уже сохранена.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Снова создание, тот же месяц → **Сформировать** | **Бизнес:** второй ЗП нет. **Код (UI):** сотрудника нет в calculate (уже есть `PAYMENT`) |
| 2 | Повторный POST create через API | **Бизнес:** отказ. **Код:** unique нет, проверки «уже есть PAYMENT» нет — вторая запись возможна |

---

## ТК-Z7. Пустой период

**Предусловия:** нет отправленных рабочих смен за месяц.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Сформировать** | Пустая таблица, не ошибка расчёта |
| 2 | **Добавить сотрудника**, если список add пустой | Сообщение «В указанный период больше нету сотрудников для расчёта зарплаты» |

---

## ТК-Z8. Смена оклада не меняет сохранённую сумму

**Предусловия:** ЗП сохранена; известен `sum`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | В профиле сменить дневной оклад и/или ставки АМС (**Стоимость смен**) | Карточка и мойка обновлены |
| 2 | Открыть ту же строку ЗП в списке | **Бизнес и код для суммы:** сохранённый `HrPayment.sum` тот же |
| 3 | Сравнить колонки ставки в отчёте | **Код:** отображение дневного оклада в GET-отчёте может перечитаться с текущих данных (первая мойка, только день). Начисленный `sum` от этого не пересчитывается |

Несколько моек за месяц: **`sum` = сумма выплат каждой смены** (ставки той АМС, где смена). Колонка «посменное начисление» в calculate — ставка первой мойки, только день.
