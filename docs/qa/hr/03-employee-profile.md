# Профиль сотрудника — сценарии для тестировщика

> Меню: из списка **Сотрудники** (в сайдбаре пункта нет).  
> Формат ТК: **Предусловия → Шаги → Ожидаемый результат**.

Общие предусловия: план **SPACE** / **BUSINESS** / **CUSTOM**, права `Hr`.

---

## О странице

### Профиль (`/hr/employees/profile`)

| | |
|--|--|
| **Зачем** | Карточка работника: данные, оклады на карточке, статус, мойки. |
| **Что менеджерит** | **HrWorker** + связь с POS. Backend: `worker-update`, `worker-pos-connection`. |
| **Кто пользуется** | HR с `read`; сохранение — `update` / `manage`. |
| **Связи** | Список сотрудников; должности; табель (выбор работника на смену); аванс/ЗП. |
| **Правила** | Без `workerId` карточку не загрузить. Статусы: **Действующий** (`WORKS`) / **Уволен** (`DISMISSED`). Уволенный остаётся в уже созданных выплатах. Список сотрудников и выбор в новой смене табеля по умолчанию только `WORKS`. |

Вкладки в UI: **Информация**, **Доп. Информация**, **Зарплата**, **Подключенные точки**.

**График** (`?tab=sch`): мёртвый UI, не используется как функция продукта. Не тестировать как рабочий график смен.

Поле **Месячный оклад** на вкладке зарплаты есть; правилом расчёта выплат не является.

---

## ТК-R1. Вкладки профиля

**Предусловия:** открыт профиль с валидным `workerId`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть вкладку **Информация** | ФИО, должность, **Статус**, дата приема |
| 2 | Открыть **Доп. Информация** | Гражданство, паспорт, СНИЛС, адрес регистрации |
| 3 | Открыть **Зарплата** | «Месячный оклад», «Дневной оклад» (и бонус, если поле есть) |
| 4 | Открыть **Подключенные точки** | Мультивыбор моек, блок «В настоящее время подключены» |

---

## ТК-R2. Сохранить карточку

**Предусловия:** право `update` / `manage`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Изменить ФИО или должность → **Сохранить** | Успех; после обновления страницы те же данные |
| 2 | Изменить дневной оклад → сохранить | Значение в карточке новое. Уже сохранённые аванс/ЗП **не** пересчитываются (см. ТК-Z8) |

---

## ТК-R3. WORKS / DISMISSED

**Предусловия:** сотрудник в статусе Действующий.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Статус → **Уволен** → Сохранить | Статус «Уволен» |
| 2 | Открыть список Сотрудники | Уволенного в таблице нет (GET без status → только `WORKS`) |
| 3 | Открыть профиль по старому URL с `workerId` | Карточка открывается, статус Уволен |
| 4 | Уже созданные аванс/ЗП за прошлые месяцы | Строки на месте |

Уволенный в **новую** смену табеля:

- **Бизнес:** указывать нельзя.
- **Код:** UI табеля не показывает (дефолт `WORKS`). Серверного запрета на create смены нет.

---

## ТК-R4. Точки АМС

**Предусловия:** есть несколько POS организации.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Вкладка **Подключенные точки** | Список доступных моек |
| 2 | Выбрать мойки → **Сохранить** | «В настоящее время подключены» совпадает с выбором |
| 3 | Снять все мойки у нового сотрудника | Снова предупреждение про невыбранные точки |

Без привязки к мойкам работник не попадает в calculate (фильтр по доступу к POS).

---

## ТК-R5. Профиль без workerId / несуществующий

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть `/hr/employees/profile` без `workerId` | Данные сотрудника не загружаются |
| 2 | Открыть с несуществующим `workerId` | Ошибка или пустое состояние (зафиксировать факт) |

---

## ТК-R6. График

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть `?tab=sch` или искать вкладку графика | Вкладки графика в наборе tabs нет. URL `tab=sch` может показать локальный UI без API. **Не используется** как функция продукта |
