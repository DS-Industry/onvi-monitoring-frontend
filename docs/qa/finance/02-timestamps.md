# Отсечки — сценарии для тестировщика

> Меню: **Управление → Отсечки**.  
> Формат ТК: **Предусловия → Шаги → Ожидаемый результат**.

Общие предусловия: план **SPACE / BUSINESS / CUSTOM**, организация, права `CashCollection` (`read` / `manage` на маршрут; кнопка — `create` или `manage`).

---

## О странице

### Отсечки (`/finance/timestamp`)

| | |
|--|--|
| **Зачем** | Зафиксировать время снятия денег с устройства (дубль действия на железе), чтобы инкассация знала верхнюю границу интервала. |
| **Что менеджерит** | События `CarWashDeviceEvent` с типом **9**. Отдельной таблицы «отсечка» нет. API: `getTimestamp`, `postTimestamp`. |
| **Кто пользуется** | Управляющий АМС. |
| **Связи** | Не обязательны для создания инкассации. При create инкассации верхняя граница = max отсечки устройства, иначе сегодня 05:00. |
| **Правила** | Сначала выбрать объект (`posId`, опционально `city`). SWR списка — только если `posId` задан и не `*`. Кнопка шлёт **`new Date()`** — произвольную дату в UI выбрать нельзя. Каждый POST — **новая** запись; GET показывает **последнюю**. После успешного клика кнопка disable локально (не по статусу инкассации). |

Подписи: заголовок **Отсечки**, фильтр **Автомойка/ Филиал**, колонки устройство, кнопка **Проинкассировал**, **Дата предыдущей инкасации**, **Дата текущей инкассации**.

---

## ТК-T1. Выбрать АМС

**Предусловия:** `read` или `manage` на `CashCollection`; в организации есть объекты с устройствами.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть **Управление → Отсечки** | `/finance/timestamp`, заголовок «Отсечки» |
| 2 | Не выбирать объект | Таблица отсечек не грузится (нет запроса / пусто) |
| 3 | Выбрать автомойку | В URL `posId`. Строки устройств. Колонки предыдущей и текущей даты (или «-», если меток не было) |

---

## ТК-T2. Поставить отсечку

**Предусловия:** выбран объект; `create` или `manage`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Нажать **Проинкассировал** у устройства | Запрос `POST user/finance/time-stamp/{deviceId}` с текущим временем |
| 2 | Дождаться успеха | «Дата текущей инкассации» заполняется. Кнопка на этой сессии становится неактивной |

---

## ТК-T3. Повторная отсечка

**Предусловия:** на устройстве уже была хотя бы одна отсечка.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Обновить страницу (локальный disable сбрасывается) | Кнопка снова доступна |
| 2 | Снова **Проинкассировал** | Создаётся **ещё одно** событие type 9. В списке нужна **последняя** дата |
| 3 | Смотреть БД / повторный GET | Старые метки **не удаляются**; ответ GET — max по устройству |

---

## ТК-T4. Отсечка не обязательна для инкассации

**Предусловия:** объект без отсечек (или можно не нажимать кнопку).

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Не ставить отсечки | Экран отсечек это позволяет |
| 2 | Создать инкассацию по этому объекту | Документ создаётся (ТК-C3). Верхняя граница из кода — сегодня 05:00, её можно править на карточке инкассации |

---

## Краткая справка (для отладки)

- `GET user/finance/time-stamp/{posId}` — последние метки по устройствам POS.
- `POST user/finance/time-stamp/{deviceId}` body `{ dateTimeStamp }` — в UI всегда now.
- Feature: `CashCollection`. Subject: `CashCollection`.
