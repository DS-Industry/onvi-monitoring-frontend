# Табель — сценарии для тестировщика

> Меню: **Управление → Табель учета рабочего времени**.  
> Формат ТК: **Предусловия → Шаги → Ожидаемый результат**.

Общие предусловия: план **SPACE / BUSINESS / CUSTOM**, организация, права `ShiftReport`.

После **Отправить** у смены единственное действие — **Вернуть** (как у инкассации).  
В расчёт ЗП/аванса HR попадают только **отправленные** смены с типом **Рабочий день**. Смена сама ЗП не считает.

---

## О странице

### Календарь (`/finance/timesheet`)

| | |
|--|--|
| **Зачем** | Видеть смены работников на объекте за период, создавать смену, открывать рабочий день. |
| **Что менеджерит** | `MNGShiftReport`. API: `getShifts` (`GET user/finance/shift-reports`), `createDayShift` (`POST user/finance/shift/create`). |
| **Кто пользуется** | Управляющий АМС с `read` / `manage` на `ShiftReport`. Создание: `create` или `manage`. |
| **Связи** | Просмотр `/finance/timesheet/view?id=&posId=`; HR — ЗП/аванс по SENT + WORKING. На статьи табель **не** влияет. |
| **Правила** | Query: `posId`, `dateStart`, `dateEnd`, `city`. Сначала выбрать объект. Зелёный кружок — `SENT`, иначе жёлтый. Клик по **Рабочий день** → view. Клик по **Выходной** → модалка удаления. Кликов по больничному/отпуску/отгулу/прогулу в календаре нет. |

Типы дня (`finance.*`): **Рабочий день**, **Выходной**, **Больничный**, **Отпуск**, **Отгул**, **Прогул**.

### Просмотр смены (`/finance/timesheet/view`)

| | |
|--|--|
| **Зачем** | Оценка смены, операции с наличными, отправка и возврат. |
| **Что менеджерит** | Одна смена + cash oper. API: `getDayShiftById`, `updateDayShift`, `sendDayShift`, `returnDayShift`, `deleteDayShift`, `createCashOper`, `getCashOperById`, `getCashOperRefundById`, `getCashOperCleanById`, `getCashOperSuspiciousById`. |
| **Кто пользуется** | Маршрут: `read` / `create` / `manage`. Save/send/операции: `create\|manage` и статус не SENT. Return: `update\|manage` и SENT. |
| **Связи** | Календарь; HR выплата; вкладки уборка/подозрительные — только просмотр. |
| **Правила** | Query `id` и `posId` обязательны. UI не различает `CREATED` и `SAVED` (create на сервере сразу SAVED). SENT: поля и добавление операций закрыты, видна **Вернуть**. |

Вкладки (подписи `ru.json`): **Оценка смены**, **Размен**, **Возвраты**, **Уборка**, **Подозрительные опреации**.  
**Размен** в коде пишет тип `REPLENISHMENT`. **Возвраты** — `REFUND`. Вклада «касса» нет.

Уборка и подозрительные: в коде только GET-таблицы. Бизнес как **ввод** их не описывал.

## ТК-W1. Календарь

**Предусловия:** `read` или `manage` на `ShiftReport`; есть объект с работниками.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Управление → Табель учета рабочего времени** | `/finance/timesheet`, заголовок «Табель учета рабочего времени» |
| 2 | Выбрать объект и период | Смены на календаре. SENT — зелёный, остальные — жёлтый |
| 3 | Клик по рабочему дню | Переход на `/finance/timesheet/view?id=…&posId=…` |

---

## ТК-W2. Создать рабочую смену

**Предусловия:** `create` или `manage`; выбран `posId`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Создать смену | Мастер: начало/конец → сотрудник → тип дня |
| 2 | Тип **Рабочий день**, валидные даты и работник → сохранить | Смена на календаре (статус не SENT). Сервер создаёт **SAVED** |
| 3 | Открыть смену | Вкладки оценки и операций доступны |

---

## ТК-W3. Оценка смены

**Предусловия:** рабочая смена не SENT.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Вкладка **Оценка смены** | Параметры оценки, комментарий |
| 2 | Выставить оценки / сохранить | Данные сохраняются, статус не SENT. Кнопки **Отправить** видны |

---

## ТК-W4. Размен и возврат

**Предусловия:** рабочая смена не SENT; `create` или `manage`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Вкладка **Размен** → добавить операцию (сумма, дата, комментарий) | Создаётся операция типа `REPLENISHMENT` |
| 2 | Вкладка **Возвраты** → добавить (сумма, устройство, дата, комментарий) | Создаётся `REFUND` |
| 3 | Других типов ввода денег нет | Нет пополнения кассы «с нуля» и нет типа EXCHANGE |

---

## ТК-W5. Отправить

**Предусловия:** оценка заполнена; не SENT.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Отправить** | Статус **Отправлено**. Оценка и операции только чтение. Кнопок save/send/удаления нет |
| 2 | Смотреть ЗП | Смена **сама** в ЗП не уходит. При расчёте ЗП/аванса в HR берётся, если SENT и тип **Рабочий день** |

---

## ТК-W6. SENT — только вернуть

**Предусловия:** смена SENT; `update` или `manage`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Искать правку оценки / новые операции / удаление в UI | Недоступны |
| 2 | Нажать **Вернуть** | Статус снова не SENT; можно править и снова отправить. Иных действий после отправки нет |

---

## ТК-W7. Выходной / отпуск — отметка, не в ЗП

**Предусловия:** `create` или `manage`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Создать смену типа **Выходной** или **Отпуск** | Смена есть как отметка |
| 2 | Клик по выходному на календаре | Модалка удаления (не экран оценки) |
| 3 | Расчёт ЗП | Такие типы в выплату **не** входят (в расчёт идут SENT + **Рабочий день**) |

---

## ТК-W8. Уволенный не в списке

**Предусловия:** в HR есть работник со статусом уволен и действующий на том же объекте.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть выбор сотрудника при создании смены | Уволенного **нет** в Select. Серверный запрет на create **не** требовать |

## Краткая справка (для отладки)

- `GET user/finance/shift-reports`, `POST user/finance/shift/create`, `GET/PATCH/DELETE user/finance/shift-report/{id}`, `POST …/send/{id}`, `PATCH …/return/{id}`, `POST/GET …/oper/{id}`, `GET …/refund/{id}`, `GET …/clean/{id}`, `GET …/suspiciously/{id}`.
- Статусы: `CREATED` (в UI не выделен), `SAVED`, `SENT`. Feature: `ShiftReport`.
- Уборка / подозрительные: только чтение; бизнес ввод не описывал.
