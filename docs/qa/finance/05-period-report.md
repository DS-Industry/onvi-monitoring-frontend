# Отчет за период — сценарии для тестировщика

> Меню: **Управление → Отчет за период**.  
> Формат ТК: **Предусловия → Шаги → Ожидаемый результат**.

Общие предусловия: план **SPACE / BUSINESS / CUSTOM**, организация, права `ManagerPaper`.

Ключ отчёта — **пользователь (`userId`)**, не АМС. Несколько объектов одного человека — это норма.

---

## О странице

### Список периодов (`/finance/report/period`)

| | |
|--|--|
| **Зачем** | Завести период учёта по менеджеру: даты, деньги на начало и сколько осталось, отправить/вернуть. |
| **Что менеджерит** | `ManagerReportPeriod`. API списка: `getAllManagerPeriods`, `createManagerPaperPeriod`, `updateManagerPaperPeriod`, `deleteManagerPaperPeriod`. **`sendManagerPaperPeriod` / `returnManagerPaperPeriod` в этот файл не импортированы.** |
| **Кто пользуется** | `read` / `manage` на маршрут. Добавление и меню edit/delete/send — `create\|manage`. Пункт return в меню — `update\|manage`. |
| **Связи** | Карточка `?ownerId=&status=`; статьи с `userId` периода и датами. |
| **Правила** | Фильтры: период дат, **сотрудник**, пагинация (`dateStart`, `dateEnd`, `userId`, `page`, `size`). Статусы `SAVE` / `SENT` (в таблице SAVE рисуется как «Сохранено»). Пустой набор статей — допустим. В меню списка send/return **есть пункты, обработчиков нет** — фактические send/return на экране edit. |

Колонки: id, период (клик → edit), входная/выходная сумма, статус, **Недостача**, пользователь. Drawer: **Начало периода***, **Конец периода***, суммы*, пользователь*. Кнопка **Добавить**.

### Карточка периода (`/finance/report/period/edit`)

| | |
|--|--|
| **Зачем** | Отправить / вернуть / удалить период; увидеть статьи пользователя за даты. |
| **Что менеджерит** | Деталь периода + `managerPaper[]`. API: `getManagerPeriodById`, `sendManagerPaperPeriod`, `returnManagerPaperPeriod`, `deleteManagerPaperPeriod`. |
| **Кто пользуется** | Send: `create\|manage` и `status === SAVE`. Return: `update\|manage` и `SENT`. Delete: `delete\|manage` и `SAVE`. Сравнение статуса — **сырой** enum из URL, не перевод. |
| **Связи** | Статьи всех объектов этого `userId` за интервал. Инкассационные автостатьи тоже попадают, если user и дата совпали. |
| **Правила** | Expand строк, только если есть статьи. Создания статей «внутри» периода нет. Чек в таблице не показывается. |

Кнопки: **Отправить**, **Возвраты** (`finance.returns`), удаление.

## ТК-P1. Список по менеджеру (не по АМС)

**Предусловия:** `read` или `manage`; в данных есть периоды / статьи у конкретного сотрудника.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Управление → Отчет за период** | `/finance/report/period`, заголовок «Отчет за период» |
| 2 | Смотреть фильтры | Есть **сотрудник**, период дат. **Нет** обязательного фильтра «одна АМС» как ключа отчёта |
| 3 | Выбрать сотрудника | Список периодов этого `userId` |

---

## ТК-P2. Создать период

**Предусловия:** `create` или `manage`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Добавить** | Drawer с началом/концом периода, суммами, пользователем |
| 2 | Сохранить без дат / user | Валидация `*` полей |
| 3 | Заполнить и сохранить | Строка со статусом SAVE («Сохранено»). Суммы начала/конца — как ввели (сервер их из статей **не** считает) |

---

## ТК-P3. Пустой отчёт — норма

**Предусловия:** у выбранного пользователя за даты **нет** статей (и нет смен — на статьи это не влияет).

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Создать период на эти даты | Период создаётся |
| 2 | Открыть карточку | Период виден; блока статей нет / expand не открывается. Это **не** ошибка |
| 3 | **Отправить** (если SAVE и есть create) | Статус SENT. Пустой SENT допустим: сервер не требует строк |

---

## ТК-P4. Отправить и вернуть

**Предусловия:** период SAVE с любым набором статей; права create/update как на кнопках карточки.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | На **списке** открыть «⋯» → **Отправить** | Пункт может быть виден; **запроса send нет**. Для отправки открыть карточку |
| 2 | На карточке при SAVE нажать **Отправить** | Статус **Отправлено**. Send только меняет статус |
| 3 | Попытаться создать/править статью с датой внутри SENT-периода этого user | Ошибка «period has already been sent» |
| 4 | Попытаться **удалить ручную** статью с датой внутри этого SENT-периода | **Нельзя.** Если DELETE проходит — **баг A4** (продукт запрещает; код delete SENT не проверяет) |
| 5 | **Возвраты** | Статус снова SAVE; статьи снова можно менять (если дата в этом периоде) |

---

## ТК-P5. Несколько объектов одного пользователя

**Предусловия:** у одного `userId` есть ручные (и/или авто) статьи на **разных** POS в интервале периода.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть карточку периода этого пользователя | В раскрытии статей видны строки с **разными** объектами |
| 2 | Не ждать отдельный отчёт «на каждую АМС» | Один период = один человек за даты |

---

## Краткая справка (для отладки)

- `GET/POST/PATCH user/manager-paper/period`, `PATCH …/period/send/:id`, `PATCH …/period/return/:id`, `GET/DELETE …/period/:id`.
- Статусы: `SAVE`, `SENT`. Feature: `ManagerPaper`.
- Недостача периода (код): `sumEndPeriod − receiptSum + expenditureSum − sumStartPeriod`.
