# Статьи — сценарии для тестировщика

> Меню: **Управление → Финансовый учет → Статьи**.  
> Формат ТК: **Предусловия → Шаги → Ожидаемый результат**.

Общие предусловия: план **SPACE / BUSINESS / CUSTOM**, организация, права `ManagerPaper`.

Продажа при проведении сама создаёт статью, не дублировать вручную.

---

## О странице

### Статьи (`/finance/financial/accounting/articles`)

| | |
|--|--|
| **Зачем** | Вести приход и расход по объектам: ручные статьи и просмотр автостатей. |
| **Что менеджерит** | `ManagerPaper`. API: `getAllManagerPaper`, `getAllManagerPaperGraph`, `createManagerPaper`, `updateManagerPaper`, `deleteManagerPapers`, `getAllManagerPaperTypes`. |
| **Кто пользуется** | Главный менеджер АМС (`read` / `manage` на маршрут). Создание/правка в таблице: `create\|manage`. Удаление: `delete\|manage`. Выбор пользователя в форме create — если есть `update\|manage`. |
| **Связи** | Справочник типов; отчет за период (по `userId` и дате события); автостатья инкассации после SENT; автостатья продажи после проведения. |
| **Правила** | Обязательны группа, объект, дата, сумма (и пользователь, если поле видно). Чек и комментарий **необязательны**. Типы `paperTypeId` **64** и **67** нельзя отметить чекбоксом и нельзя править в строке (подписи «инкассация/продажа» в UI нет). |

Карточки **Доходы / Расходы / Баланс** (подписи в коде экрана). Фильтры: дата, количество, сотрудник, статья, группа, город, объект (`group`, `posId`, `paperTypeId`, `userId`, `dateStart`, `dateEnd`, `page`, `size`, `city`).

Кнопки: **Добавить новый тип бумаги** (модалка типа), **Добавить строку**, **Удалить выбранное**. Колонки: **Группа**, назначение/объект, **Статья**, **Дата**, **Сумма**, операции.

---

## ТК-A1. Список и фильтры

**Предусловия:** `read` или `manage` на `ManagerPaper`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Управление → Финансовый учет → Статьи** | `/finance/financial/accounting/articles`, таблица и карточки сумм |
| 2 | Задать период, объект, группу, тип, сотрудника | Список и график перезапрашиваются; в URL соответствующие query |
| 3 | Сбросить / расширить период | Набор строк меняется |

---

## ТК-A2. Создать приход и расход

**Предусловия:** `create` или `manage`; в справочнике есть типы RECEIPT и EXPENDITURE.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Добавить строку** | Модалка создания |
| 2 | Не заполнять сумму / объект / дату → сохранить | Валидация обязательных полей |
| 3 | Группа, объект, тип **Приход**, дата, сумма → сохранить | Строка в таблице, карточка доходов растёт |
| 4 | Повторить с типом **Расход** | Строка расхода, карточка расходов растёт |

---

## ТК-A3. Чек необязателен

**Предусловия:** как A2.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Создать статью **без** файла чека и **без** комментария | Статья сохраняется |
| 2 | При желании приложить файл и комментарий | Сохраняется; на экране периода превью чека **нет** (колонки нет) |

---

## ТК-A4. Автостатья инкассации не редактируется

**Предусловия:** есть SENT-инкассация; статья типа «Инкассация» (`paperTypeId` 64).

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Найти строку автостатьи | Чекбокс строки disabled, «редактировать» нет |
| 2 | Не менять сумму/дату через UI | UI не даёт. Backend тоже режет type id 64 и 67 |

---

## ТК-A5. Удаление только после возврата инкассации

**Предусловия:** SENT и автостатья на месте.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Пытаться удалить автостатью чекбоксом на **Статьях** | Строку нельзя выбрать |
| 2 | **Вернуть** инкассацию (ТК-C9) | Автостатья пропадает (delete по `cashCollectionId`) |
| 3 | После возврата ручные статьи того же периода | Удаляются обычным **Удалить выбранное**, если не type 64/67 |

---

## Краткая справка (для отладки)

- `GET/POST/PATCH user/manager-paper`, `DELETE user/manager-paper/many`, `GET user/manager-paper/statistic`.
- Feature: `ManagerPaper`. Hardcode UI/backend: ids **64**, **67**.
