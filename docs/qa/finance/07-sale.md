# Продажа — сценарии для тестировщика

> Меню: **Управление → Продажа**.  
> Формат ТК: **Предусловия → Шаги → Ожидаемый результат**.

Общие предусловия: план **SPACE / BUSINESS / CUSTOM**, организация, права `ManagerPaper` на список.  
Продажа при проведении **сама** создаёт статью — вручную ту же продажу в **Статьях** не дублировать.

Отдельного статуса документа нет: создание = проведение (склад `WRITEOFF` + статья).

---

## О странице

### Список (`/finance/saleDocument`)

| | |
|--|--|
| **Зачем** | Видеть документы продажи товаров, создавать новый, открывать просмотр. |
| **Что менеджерит** | `MNGSaleDocument`. API: `getSaleDocuments` (`GET user/sale/documents`). |
| **Кто пользуется** | Маршрут списка: `read` / `manage` на `ManagerPaper`. Кнопка создать на экране — `create\|manage` ManagerPaper. |
| **Связи** | Склад (остатки и **Цены для продажи**); статья после проведения; create/view по URL. |
| **Правила** | Фильтры: город, объект/склад, период. Query: `page`, `size`, `warehouseId`, `dateStart`, `dateEnd`. |

### Создание (`/finance/saleDocument/create`)

| | |
|--|--|
| **Зачем** | Оформить продажу: склад, менеджер, ≥1 позиция с остатком и ценой. |
| **Что менеджерит** | Create документа. API: `postSaleDocument` (`POST user/sale/document`), `getManagers` (`GET user/sale/manager/{warehouseId}`), `getAllStockLevelSales` (`GET user/warehouse/inventory-item/sale/{warehouseId}`). |
| **Кто пользуется** | На маршруте **permissions пустые** (прямая ссылка не режется CASL маршрута). Заголовок «Создание документа продажи». |
| **Связи** | Склад → остаток **и** цена; проведение пишет складской расход и статью типа «Продажа». |
| **Правила** | В список позиций попадают только номенклатуры с остатком и ценой. Один POST = проведение. Отдельной кнопки «отправить» нет. |

### Просмотр (`/finance/saleDocument/view`)

| | |
|--|--|
| **Зачем** | Смотреть проведённый документ; вернуть (снять статью и складское проведение). |
| **Что менеджерит** | `getSaleDocument`, `returnSaleDocument` (`POST user/sale/document/return/{id}`). |
| **Кто пользуется** | Маршрут без permissions. Заголовок «Документ продажи». Return на UI: `update\|manage` **Warehouse**. |
| **Связи** | Статья с `mngSaleDocumentId`; без возврата править/удалить документ нельзя (отдельного PATCH/DELETE документа нет). |
| **Правила** | Query `documentId`. Return: unsend склада + удаление статьи + удаление документа. |

## ТК-Y1. Список продаж

**Предусловия:** `read` или `manage` на `ManagerPaper`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Управление → Продажа** | `/finance/saleDocument`, заголовок «Продажа» |
| 2 | Задать период / склад | Таблица документов (или пустая) |

---

## ТК-Y2. Создать без остатка или без цены — нельзя

**Предусловия:** на складе есть позиция без цены и/или с нулевым остатком.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть создание | Форма: дата, склад, менеджер, позиции |
| 2 | Искать в выборе номенклатуру без остатка или без цены | Её **нет** в списке продажи (`inventory-item/sale`) |
| 3 | Сохранить без позиций | Документ не создаётся |

---

## ТК-Y3. Создать с остатком и ценой

**Предусловия:** номенклатура с остатком на объекте и ценой в **Склад → Цены для продажи**; склад и менеджер заданы.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Склад, менеджер, ≥1 позиция с количеством | Позиция выбирается, сумма считается |
| 2 | Сохранить / провести | Документ в списке. На складе списание. Отдельного шага «отправить» нет |

---

## ТК-Y4. Проведение → статья

**Предусловия:** успешный ТК-Y3.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть **Статьи** | Автостатья типа «Продажа» (приход), сумма документа, без ручного ввода |
| 2 | Пытаться править эту статью в учёте | Строка с type id продажи (67) не редактируется / не выбирается чекбоксом |

---

## ТК-Y5. Без возврата нельзя править / удалить

**Предусловия:** документ проведён.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть просмотр | Данные только чтение. Нет формы правки позиций |
| 2 | Искать удаление документа без возврата | Отдельного delete документа нет |

---

## ТК-Y6. Вернуть → статья снята

**Предусловия:** проведённый документ; право update/manage склада для кнопки возврата.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Вернуть** | Документа нет в списке (удалён). Складской документ отозван |
| 2 | **Статьи** | Автостатья этой продажи **снята** |

---

## Краткая справка (для отладки)

- `GET user/sale/documents`, `POST/GET user/sale/document`, `POST user/sale/document/return/{id}`, `GET user/sale/manager/{warehouseId}`.
- Цены CRUD `user/sale/price` экраны продажи **не** вызывают.
- Feature/CASL create документа: `ManagerPaper` create. Return: `Warehouse` update.
