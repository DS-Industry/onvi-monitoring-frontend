# Инкассация — сценарии для тестировщика

> Меню: **Управление → Инкассация**.  
> Формат ТК: **Предусловия → Шаги → Ожидаемый результат**.

Общие предусловия раздела: план **SPACE / BUSINESS / CUSTOM**, организация, права `CashCollection`.

Правила раздела (один ожидаемый результат): после отправки только **Вернуть**; без отсечки границы **05:00**; положительная недостача = забрали меньше, чем насчитано. См. [00-how-it-works.md](./00-how-it-works.md).

---

## О странице

### Список инкассаций (`/finance/collection`)

| | |
|--|--|
| **Зачем** | Видеть инкассации объектов за период, открывать карточку, создавать новую. |
| **Что менеджерит** | Список `CashCollection`. API: `getCollections`. |
| **Кто пользуется** | Управляющий АМС с `read` или `manage` на `CashCollection`. |
| **Связи** | Создание `/finance/collection/creation`; отсечки; после SENT — статья в учёте. |
| **Правила** | Фильтры `GeneralFilters`: объект, город, дата-время (`posId`, `city`, `dateStart`, `dateEnd`, `page`, `size`). В API уходит ещё `organizationId` из сессии. Кнопка **Создать** на списке без `Can` (достаточно права на маршрут). В ссылку карточки кладётся **уже переведённый** статус (`tables.SENT` → «Отправлено»). |

Колонки (подписи из `ru.json`): **№ Документа**, **Автомойка/Филиал**, **Период**, статус, **Инкассация** (`sumFact`), **Сумма по картам**, **Безналичная оплата** (`sumVirtual` / `virtualSum`), **Прибыль**, **Недостача**, создатель; плюс динамические колонки недостачи по типам устройств. Строка **Итого**.

### Создание / карточка (`/finance/collection/creation`)

| | |
|--|--|
| **Зачем** | Сформировать инкассацию, проверить расчёт и метки, внести факт, пересчитать, отправить или вернуть. |
| **Что менеджерит** | Один `CashCollection` + устройства + типы. API: `postCollection`, `getCollectionById`, `recalculateCollection`, `sendCollection`, `returnCollection`, `deleteCollectionById`. |
| **Кто пользуется** | `create` / `update` / `manage` на `CashCollection` (кнопки ужесточают: удалить/пересчитать/отправить — `create\|manage` и статус не «Отправлено»; вернуть — `update\|manage` и статус «Отправлено»). |
| **Связи** | Список; отсечки задают верхнюю границу, если были; SENT создаёт статью «Инкассация». |
| **Правила** | Форма объекта и даты скрыта, если query `status` уже «Отправлено» или «Сохранено». После **Сформировать** в URL пишется только `id`. Факт (монеты/купюры) и даты устройств редактируются, пока статус не «Отправлено». `virtualSum` / недостача — только чтение. `sumCard` в шапке карточки нет. |

Подписи: **Инкассация**, **Дата инкассации**, **Автомойка/ Филиал**, **Сформировать**, блоки **Инкассация по мойке** / **Инкассация по устройствам**, **Пересчитать**, **Пересчитать и отправить**, **Вернуть**.

## ТК-C1. Открыть список инкассаций

**Предусловия:** `read` или `manage` на `CashCollection`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | В меню открыть **Управление** | Раскрывается подменю |
| 2 | Нажать **Инкассация** | `/finance/collection`, заголовок «Инкассация» |
| 3 | Дождаться загрузки | Таблица (или пустая). Есть **Создать**, фильтры объекта / города / периода |

---

## ТК-C2. Создать инкассацию

**Предусловия:** `create` или `manage`; на объекте есть устройства; дата **позже** последней SENT по этому POS (если SENT уже была).

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Нажать **Создать** | `/finance/collection/creation`, при выбранном объекте в списке — `posId` в query |
| 2 | Не выбирать объект / дату → **Сформировать** | Форма не уходит / валидация обязательных полей |
| 3 | Выбрать объект и дату → **Сформировать** | Документ создан (SAVED). Появляются блоки по мойке и по устройствам, суммы кроме факта заполнены |
| 4 | Проверить URL | Есть `id`; статус в query может отсутствовать |

---

## ТК-C3. Нет отсечек (границы 05:00)

**Предусловия:** на устройствах объекта нет событий отсечки (type 9). Можно править даты на карточке.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Сформировать** инкассацию без отсечек | Документ создаётся. Отсечка **не обязательна** |
| 2 | Смотреть верхнюю границу по устройствам | **Сегодня 05:00**. Это правило продукта, не «сейчас» и не ошибка |
| 3 | Смотреть нижнюю границу, если SENT по объекту ещё не было | **Вчера 05:00** (предыдущая SENT отсутствует) |
| 4 | Изменить «новое» время сбора на устройстве, сохранить строку, **Пересчитать** | Граница принимается; операции пересчитываются за новый интервал |

---

## ТК-C4. Внести факт

**Предусловия:** есть SAVED-инкассация; статус в UI не «Отправлено».

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | В блоке по типам устройств ввести монеты и купюры | Поля редактируются |
| 2 | Нажать **Пересчитать** | `sumFact` типа = монеты + купюры; недостача и итоги шапки обновляются. `virtualSum` с ввода не меняется руками |

---

## ТК-C5. Недостача

**Предусловия:** после расчёта известен нал по операциям (`sum` устройств) и введён факт.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Ввести факт **меньше** расчётного нала по типу | Недостача **положительная** (забрали меньше, чем насчитано) |
| 2 | Сверить формулу | Недостача типа = Σ нал устройств − факт (только монеты+купюры) |
| 3 | Посмотреть безнал / virtual | `sumCard` и `virtualSum` есть в данных/списке; **в недостачу не входят** |

---

## ТК-C6. Отправить

**Предусловия:** SAVED; `create` или `manage`; факт внесён.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Нажать **Пересчитать и отправить** | Статус **Отправлено**. Даты и факт только чтение. Кнопки пересчёта / удаления / отправки скрыты |
| 2 | Открыть **Статьи** | Появилась автостатья типа «Инкассация» (приход, сумма = `sumFact`), без ручного ввода |
| 3 | Повторно открыть карточку | Редактировать нельзя (см. ТК-C8). Пересчёта SENT нет |

---

## ТК-C7. Повторная SENT: пересечение / дата раньше

**Предусловия:** по объекту уже есть SENT.

Конфликт не сглаживать.

### Дата не позже последней SENT (создание)

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | **Сформировать** новую инкассацию с датой **≤** `cashCollectionDate` последней SENT | **Код:** ошибка create («Creation date error cashCollection»). **Бизнес:** нельзя создать раньше даты последней SENT |

### Пересечение интервалов (не create)

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть **другую** SAVED по тому же POS и сдвинуть границы устройств так, чтобы пересечь SENT | **Код:** на recalculate/send проверки пересечения и «не раньше SENT» **нет** (запрос может пройти). **Бизнес:** SENT не пересекаются по времени (сервер) |

---

## ТК-C8. Попытка править SENT

**Предусловия:** карточка в статусе «Отправлено»; query `status` совпадает с `tables.SENT` («Отправлено»), если открыли из списка.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть SENT из списка | Формы смены объекта/даты нет. Монеты/купюры и даты устройств не редактируются |
| 2 | Искать **Пересчитать** / **Пересчитать и отправить** / удаление | Кнопок нет. Единственное действие — **Вернуть** (ТК-C9) |
| 3 | Если вызвать API recalculate/send (не через UI) | Отказ «can't be recalculate» |

---

## ТК-C9. После отправки только вернуть

**Предусловия:** SENT; `update` или `manage`.

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | На карточке нажать **Вернуть** | Статус снова **Сохранено**; автостатья инкассации удаляется; можно снова править факт и пересчитывать |
| 2 | Искать другое действие над SENT кроме возврата | Нет. После отправки действие одно — **Вернуть** |

---

## Краткая справка (для отладки)

- Список: `GET user/finance/cash-collections`. Карточка: `POST/GET/DELETE user/finance/cash-collection`, `POST …/recalculate/:id`, `POST …/send/:id`, `PATCH …/return/:id`.
- Статусы: `CREATED` (мгновенно), `SAVED`, `SENT`.
- Feature backend: `CashCollection`.
