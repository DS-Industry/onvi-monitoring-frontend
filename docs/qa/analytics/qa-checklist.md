# QA checklist: Analytics

## Доступ и маршрутизация

- [ ] Без `read/manage Pos` раздел и дочерние маршруты недоступны.
- [ ] При прямом открытии каждого URL проверяется permission guard.
- [ ] `/station/enrollments/:posId` не принимает пустой или нечисловой `posId`.
- [ ] Назад возвращает к предыдущему списку с сохранёнными фильтрами.
- [ ] Ссылки из overview передают правильные `posId`, `deviceId` и даты.

## Данные и фильтры

- [ ] Страна выбирается по умолчанию только если она доступна.
- [ ] Без страны сетевой запрос не отправляется.
- [ ] Период одинаково применяется к KPI, таблицам, графикам и деталям.
- [ ] `PAYMENT` и `CLEANING` дают разные результаты.
- [ ] Пагинация сбрасывается после изменения фильтра/периода/размера.
- [ ] Empty state и API error визуально различаются.
- [ ] Loading state не показывает устаревшие значения как новые.

## Финансовая корректность

- [ ] Суммы каналов отображаются в правильных колонках.
- [ ] Переключение валюты не меняет исходные API-значения.
- [ ] Возвраты не смешиваются с выручкой.
- [ ] Средний чек корректен при нулевом количестве операций.
- [ ] План не принимает отрицательное значение.
- [ ] Save недоступен без изменения плана.
- [ ] После успешного PATCH значение сохраняется после перезагрузки.

## Типы станций и устройства

- [ ] Для Portal вкладка Cleaning скрыта.
- [ ] Для SelfService/SelfServiceAndPortal Cleaning доступна.
- [ ] Депозитные операции и программные операции открываются на правильном устройстве.
- [ ] Даты операции и загрузки не перепутаны.
- [ ] При отсутствии устройства запрос с нулевым ID не выполняется.

## Backend smoke-check

- [ ] Ответы `/user/pos/overview/*` имеют ожидаемую структуру и числовые KPI.
- [ ] Ответы monitoring/program содержат `totalCount` там, где его ожидает UI.
- [ ] PATCH `/user/pos/:id/monthly-plan` возвращает сохранённый месяц и сумму.
- [ ] Ошибки 401/403/404 отображаются безопасно, без внутренних деталей.
