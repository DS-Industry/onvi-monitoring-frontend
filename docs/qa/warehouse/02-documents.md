# Warehouse: складские документы

## 1. Список документов — `/warehouse/documents`

### О странице

| Вопрос | Ответ |
|---|---|
| **Зачем** | Контролировать складские операции организации. |
| **Что менеджерит** | Фильтрацию, просмотр статуса, создание и возврат отправленных документов. |
| **Кто пользуется** | Менеджеры склада и пользователи с доступом к `Warehouse`. |
| **Связи** | Склады, города, ответственные лица, номенклатура и остатки. |
| **Правила** | По умолчанию используется текущая дата; доступные типы — `COMMISSIONING`, `WRITEOFF`, `MOVING`, `INVENTORY`, `RECEIPT`. |

### Тест-кейсы

#### ТК-DOC-01 — список и фильтры

**Предусловия:** есть документы за выбранный период в нескольких складах.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть `/warehouse/documents` | Загружается таблица с номером, названием, датой, статусом, типом, складом и ответственным |
| 2 | Выбрать склад или город | Список обновляется по фильтру |
| 3 | Изменить период | Передаются `dateStart` и `dateEnd`, список соответствует периоду |
| 4 | Переключить страницу или размер | Параметры `page` и `size` обновляются |
| 5 | Нажать название документа | Открывается `/warehouse/documents/view` с `documentId` и типом |

#### ТК-DOC-02 — создание документа

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Нажать Add | Открывается выбор типа документа |
| 2 | Выбрать тип и подтвердить | Документ создаётся, открывается экран заполнения с его идентификатором |
| 3 | Отменить модальное окно | Документ не создаётся |
| 4 | Открыть экран без права создания | Кнопка Add отсутствует |

#### ТК-DOC-03 — возврат отправленного документа

**Предусловия:** есть документ со статусом `SENT` и право `update`/`manage`.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Найти отправленный документ | Отображается статус `SENT` и действие возврата |
| 2 | Нажать возврат | Появляется подтверждение |
| 3 | Подтвердить | Выполняется `unsend`, документ обновляется и снова доступен для изменения |
| 4 | Отменить подтверждение | Статус и данные не меняются |

## 2. Создание и редактирование — `/warehouse/documents/creation`

### Тест-кейсы

#### ТК-DOC-04 — заполнение документа

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть creation с `documentId` | Загружаются тип, склад и текущие строки документа |
| 2 | Выбрать склад и ответственного | Значения сохраняются в форме |
| 3 | Добавить номенклатуру и количество | Строка появляется в таблице |
| 4 | Для `MOVING` выбрать склад назначения | Заполняется склад-получатель |
| 5 | Для `INVENTORY` проверить фактическое количество и расхождение | Отображаются поля инвентаризации |
| 6 | Сохранить | Документ получает статус `SAVED`, данные доступны после обновления |
| 7 | Отправить | Документ получает статус `SENT` и становится недоступен для обычного редактирования |

## 3. Просмотр — `/warehouse/documents/view`

#### ТК-DOC-05 — просмотр документа

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть ссылку из списка | Отображаются реквизиты документа и его строки |
| 2 | Проверить тип и статус | Значения соответствуют списку документов |
| 3 | Открыть невалидный `documentId` | Показана ошибка или empty state без падения приложения |
| 4 | Вернуться назад | Возврат ведёт к предыдущему экрану с сохранённым контекстом |
